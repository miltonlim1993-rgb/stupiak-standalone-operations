# Stupiak's Automatic Local Print Connector v19

The Local Print Connector gives the Web app the same stable RAW TSPL output used by the Android APK.

A normal browser cannot open an arbitrary printer TCP 9100 socket. The Web app therefore sends the already-generated RAW TSPL document to a small helper on the same Windows or macOS computer. The helper opens the printer socket without using a browser print dialog, HTML page, driver scaling or Raster fallback.

## Simple Web Direct Wi-Fi/LAN

After the connector is installed once, staff only enter:

- the printer's own IP address;
- Raw TCP port `9100`, or LPR port `515`;
- the physical label settings.

The Web app automatically uses:

```text
http://127.0.0.1:8788
```

No pairing token is shown or entered for same-computer Web printing. The automatic Web endpoint is bound to loopback only and accepts the Stupiak's Ops production origin only.

The internal bridge remains on `127.0.0.1:8787`; its generated token is used privately by the automatic connector and is never exposed to the browser.

## Supported routes

- **Web Direct Wi-Fi/LAN:** Web app → automatic connector → printer Raw TCP 9100 or LPR 515
- **PC/Mac Advanced Bridge RAW Queue:** Web/phone → token-protected bridge → installed Windows/CUPS RAW queue
- **Advanced Bridge Raw TCP:** Web/phone → token-protected bridge → printer TCP socket
- **Advanced Bridge LPR:** Web/phone → token-protected bridge → printer LPR queue
- Local network printer discovery

Every route receives the same Base64-encoded TSPL document generated by Stable TSPL Core v16.

## Windows

Requirements:

- Windows 10 or Windows 11
- Node.js 22 or newer
- Computer and printer on the same private network
- For RAW Queue mode, the target printer must already be installed in Windows

From PowerShell in the project folder:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install-print-bridge-windows.ps1
```

The installer:

1. Copies the internal bridge and automatic Web connector into `%LOCALAPPDATA%\StupiaksPrintBridge`.
2. Starts both automatically at Windows login.
3. Confirms Web Connector URL `http://127.0.0.1:8788`.
4. Confirms that a pairing token is not required on that computer.

Then open Label Printer Settings, choose Direct Wi-Fi/LAN, enter the printer IP, press **Test route**, then **Test label**.

For an installed RAW printer queue or a connector on another computer, choose **Advanced Bridge**. That advanced route still requires its pairing token.

Remove the startup task:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install-print-bridge-windows.ps1 -Remove
```

## macOS

Requirements:

- Node.js 22 or newer
- Mac and printer on the same private network
- For RAW Queue mode, the printer must already be installed in macOS/CUPS

From Terminal in the project folder:

```bash
bash scripts/install-print-bridge-macos.sh
```

The installer creates a LaunchAgent and starts both the internal bridge and automatic connector. Same-computer Chrome/Safari uses `http://127.0.0.1:8788` automatically and does not need a pairing token.

## Android native routes

Android does not need the connector for:

- **Direct Wi-Fi/LAN:** native Raw TCP or LPR to the printer's own IP
- **Bluetooth Classic:** native paired SPP connection

The Android APK and Web Direct LAN send the same TSPL bytes. Only the transport mechanism differs.

## Automatic Web endpoints

Loopback-only port `8788`:

- `GET /health`
- `POST /test`
- `POST /print`

The automatic endpoint is origin-locked and tokenless. It forwards internally to the token-protected bridge.

## Advanced bridge endpoints

Internal/default port `8787`:

- `GET /health`
- `GET /printers`
- `GET /discover?port=9100`
- `POST /test`
- `POST /print`

Advanced remote-device and queue access requires the bridge pairing token.

## Browser notes

- Chrome/Edge may ask for Local Network Access permission. Allow it for Stupiak's Ops.
- Do not enter the printer IP into the Connector URL field; simple Web Direct LAN no longer shows that field.
- Do not expose ports 8787 or 8788 to the public internet.
- Web Food Labels intentionally do not use System/Browser Print because browser pagination and driver scaling caused labels to split across multiple stickers.
